## 一、载体方案重构（本次最大改动）

### 问题背景

CraftEngine 的自定义方块要挂在一个**原版方块状态**上（"载体"）。之前用玻璃类做载体，导致：

- 玩家放普通玻璃 → 变成魔力池
- 玩家放圆石墙 → 变成魔力水晶
- 载体是实心方块时，下方方块的面被错误剔除 → 出现"透明洞"

### 最终方案

**树叶载体 + 空模型覆盖 + 实体渲染**

```yaml
botania:apothecary_default:
  state:
    # ① 载体：树叶的自然生成态（玩家手放的树叶是 persistent=true，不会命中）
    state: "minecraft:birch_leaves[distance=6,persistent=false,waterlogged=false]"
    # ② 空模型：盖掉树叶自己的贴图
    model: botania:block/empty
    # ③ 实体渲染：模型由 item_display 显示
    entity_renderer:
      type: item_display
      item: botania:render/apothecary_default
      display_transform: none
```

三个条件同时满足：

| 需求 | 实现方式 |
|---|---|
| 满格碰撞 | 树叶本身是满格方块 |
| 载体不可见 | `model: botania:block/empty`（`elements: []`） |
| 有模型 | `entity_renderer` 实体渲染 |
| 不占用玩家常用方块 | 树叶的 `persistent=false` 只在自然生成时出现 |

**22 个核心方块全部改成这套方案**，状态分配：7 种树叶 × 4 个 distance = 28 个唯一状态。

### 发射器朝向修正

`item_display` 的模型默认朝向与方块 `facing` 相差 180°，四向映射调整为：

| 方块朝向 | 模型旋转 |
|---|---|
| north | `0,180,0` |
| east | `0,90,0` |
| south | `0,0,0` |
| west | `0,270,0` |

## 四、3D 模型：从 Java 代码提取几何体

有些方块（水晶、沙漏、风箱、酿造台）的几何体写在 Java 的 `client/model/*.java` 里，资源包里只有 `builtin/entity` 占位。

新增 `tools/extract_java_models.py`，解析 `CubeListBuilder.addBox()` + `texOffs()` + `PartPose.offset()`，转成标准模型：

| 方块 | 提取到的立方体 |
|---|---|
| `mana_pylon`（魔法水晶） | 7 |
| `natura_pylon`（自然水晶） | 11 |
| `gaia_pylon`（盖亚水晶） | 11 |
| `bellows`（魔源风箱） | 2 |
| `brewery`（植物酿造台） | 3 |
| `hourglass`（悬浮沙漏） | 提取失败（模型写法不同） |

**关键坑**：UV 必须归一化到 **0~16 空间**，否则 26.1+ 客户端会报「越界 UV，无法烘焙」并渲染成黑紫：

```python
uv_scale_x = 16.0 / tex_width
uv_scale_y = 16.0 / tex_height
```

修复前 600 条警告，修复后 0 条。

## 八、发射器：接力链路检测

**新行为**：接力时只有下游最终能到达真正的接收方（魔力池 / 符文祭坛）才传，否则：

- 不传魔力
- 不发射粒子
- **挡住射线**（不会穿过它去找后面的池子）

```
A → B（B 后面空着）    → A 不传、不冒粒子
A → B → 池子           → 一路传到底，A/B 都有粒子
A → B → C → 池子       → 两级接力
```

递归深度限制 8 层（防环）。
