## 核心架构

### 1. 方块行为模式

每个核心方块 = **Behavior（行为）+ Controller（方块实体）**：

```
ManaPoolBehavior          → 处理放置/交互/命令
ManaPoolController        → 方块实体（魔力、粒子、tick）
```

Behavior 实现 `BlockBehavior` 接口，在 `CeBotaniaPlugin` 里注册。

### 2. 逐刻调度用 TickBus（不用 CE 的 ticker）

**因为**：`BlockEntityController#createBlockEntityTicker` 返回的 ticker **只会被调用一次**（坑 #2）。

控制器在构造和 `onLoad` 时登记，在 `onUnload` 或 `onRemove` 时注销。`TickBus` 在 Bukkit 主线程逐刻遍历全部已登记控制器。旧版循环每刻处理前 512 个后退出，导致后面的控制器一直得不到执行。回归测试覆盖 511、512、513、1024 和 1025 个控制器。

### 3. 花用「透明载体 + 实体渲染」

CraftEngine 自定义方块要挂在原版方块状态上：

| 形状 | 载体 | 碰撞 |
|---|---|---|
| 整块（石头、木头） | 音符盒 `auto_state: solid` | 满块 |
| 花（十字模型） | 甘蔗（`transparent` 共享） | 0，可穿过 |
| 半高机器（池子、发射器、花药台） | 各自一个台阶状态 | 半格 |

**为什么**：音符盒是满方块，客户端会剔除下方顶面 + 变成实心碰撞。

### 4. 配方系统

- `RecipeBookLoader` 从插件 JAR 内读取 `data/recipes.json`，构建供匹配使用的配方集合。
- `Tags` 从 `data/tags.json` 加载标签。
- `RecipeBook` 用多重集合匹配投料，重复的同色花瓣需要按数量分别消耗。

### 5. 内容生成管线

物品、方块、分类、语言配置和精灵门 X 向模型可从仓库内的素材和语言快照离线生成。用 Python 3.10 或更新版本运行 `python3 tools/gen_content.py` 和 `python3 tools/gen_core_blocks.py`，并用各自的 `--check` 核对产物。需要更新上游输入时，再运行对应的提取脚本。

```bash
python3 tools/extract_assets.py /path/to/Botania-src   # 材质/模型
python3 tools/extract_recipes.py                       # 配方
python3 tools/extract_flowers.py                       # 花参数
python3 tools/fetch_lang.py --update-content           # 双语名称快照
python3 tools/gen_content.py                           # 物品/方块/分类
python3 tools/gen_core_blocks.py                       # 核心方块
python3 tools/gen_plugin_data.py                       # 配方进 jar
```

加**新的核心玩法方块**：改 `tools/gen_core_blocks.py` 的 `CORE` 表 + `pack/configuration/blocks/_core_overrides.txt`。

## 关键约束（不能动的）

1. **CraftEngine 的 `delay-configuration-load: true`** 必须开
   → 插件要抢在 CE 载包之前注册方块行为，否则行为全失效。

2. **共享视觉状态的方块不要复用**（坑 #3）
   → 共享会让 CE 替换方块时**认不出旧实体**（表现为数据丢失、透明方块旁边渲染错）。
   → 每个核心方块用独立 `SLAB_CARRIERS`/`CARRIER_STATES`。

3. **`blockEntity().world` 可能为 null**（坑 #4）
   → 构造期和 `onLoad` 时缓存 `(world, pos)`。

4. **主线程扫描应限制范围**
   → 精灵交易只检查当前已开启门的局部掉落物。火花按源所在及相邻区块索引候选，最后检查 16 格三维距离。候选顺序影响池子之间的分配，修改时保留原有遍历顺序。

5. **资源包路径**
   → 部署时必须解压到 `resources/botania/`（不要多套 `pack/`），zip 已去前缀。

## 踩过的坑（别重复踩）

| 坑 | 现象 | 解法 |
|---|---|---|
| #1 音符盒载体 | 花下方顶面消失 + 实心碰撞 | 改甘蔗载体 |
| #2 ticker 只跑一次 | 方块不产魔 | 用 TickBus |
| #3 共享视觉状态 | 数据丢失 | 每方块独立载体 |
| #4 world=null | 魔力一直 0 | 缓存 world/pos |
| #5 交易抢活/配置写错 | 倾覆行为失效 | 拆 listen/confirm，配置内嵌 |
| #6 跳跃误触 | 跳着掉进池子触发 | PlayerJumpEvent 只认 Initial |
| #7 0 计数不交易 | 仍换一次 | 格内无物品直接拒绝 |
| #8 木棍换武器 | 匹配匹配错了 | 归一化后排除 "tag=" |
| #9 模型旋转反 | 朝向全反 | 关渲染旋转，用 state 属性 |
| #10 跳平台误判 | 跳上平台被拽下来 | onGround 检查 |
| #11 打两下消失 | 花瓣归零移除 | 检查兜底扫描 |
| #12 关闭后重开无粒子 | 只建一次 | 每次开启重新建 |
| #13 传送门往四周进 | 进到边缘 | 同轴 iterate 从远处往近处 |
| #14 薄片方向 | 竖条/横片反 | 按框架朝向选 along_x/along_z |

## 构建、分发和部署

使用 JDK 25。在仓库根目录构建插件并生成与之配套的资源包：

```bash
(cd plugin && ./gradlew build)
python3 -c 'from shutil import make_archive; make_archive("plugin/build/libs/CE-Botania-pack", "zip", "pack")'
```

分发 `plugin/build/libs/CE-植物魔法-0.1.0.jar` 与 `plugin/build/libs/CE-Botania-pack.zip`。`dist/` 的 Alpha 包用于历史版本，本地分发总包 `dist/ce-botania-latest/CE-Botania-0.1.0.zip` 内含部署说明、插件 JAR 和资源包 ZIP。本次资源包 ZIP 的根目录包含 `blueprint/`、`configuration/`、`pack.yml` 和 `resourcepack/`，共 4,221 个文件。总包 SHA-256 为 `c7b844d7e3a41cdf02db24151e7efd78cf1a87d974753e23d80e08ad31af2834`。

部署到 Leaves 26.3 / CraftEngine 26.9.2 时，先停服，再替换 `plugins/` 里的旧 JAR，备份并替换 `plugins/CraftEngine/resources/botania/`，确认 CraftEngine 的 `misc.delay-configuration-load` 为 `true`。资源更新后清理 CraftEngine 的旧资源缓存，再启动服务端并重新获取客户端资源包。完整路径和目录结构见 [README 的部署说明](../README.md#部署)。

## 验证方法

### 自动验收

从仓库根目录运行：

```bash
python3 tools/acceptance/run.py --server-template /path/to/Server
```

模板是已初始化且接受 EULA 的 Leaves 26.3 服务端，装有 CraftEngine 26.9.2。模板的 CraftEngine 配置需启用延迟加载。脚本会运行 Gradle 构建和单元测试，构建独立探针，复制模板所需文件到临时目录，用当前资源包创建固定种子的平坦世界并执行 `ceaccept`。有完整的 Gradle 缓存时可传 `--offline`。测试结束清理临时世界，日志和生产插件 SHA-256 留在 `plugin/build/acceptance/run-*/`。详见 [隔离测试服验收说明](../tools/acceptance/README.md)。
