## 一、泰拉钢线

### 泰拉凝聚板

**结构**（从官方辞典实测得出）：

```
y=-59:        中心 = 泰拉凝聚板
y=-60:  活石   青金石  活石
        青金石  活石   青金石
        活石   青金石  活石
        └─ 5 活石（4 角 + 中心）+ 4 青金石 ─┘
```

**流程**：

```
① 板顶丢：魔钢锭 + 魔力钻石 + 魔力珍珠
② 魔力必须经过火花送到凝聚板（池子直连不算）
③ 攒够 50 万魔力 + 三样材料齐 → 右键凝聚板成型 → 泰拉钢锭
```

## 二、精灵传送门

### 结构（官方 5×5 竖平面，11 块活木）

```
y=-56:  .   活木   微光  活木  .
y=-57:  活木  .     .    .    活木
y=-58:  微光  .     .    .    微光
y=-59:  活木  .     .    .    活木
y=-60:  .   活木  【核心】 活木  .
```

**四角和底边角全是空的**，活木共 **11 块**。

**周围 5 格内还需要**：

```
2 组「魔力池 + 正上方的自然水晶」
（水晶坐在池子上取魔，这是上游的取魔方式）
```

### 双朝向支持

框架**东西朝向**或**南北朝向**都能识别：

```java
int alongX = countFrameInPlane(true);    // 沿 x 展开
int alongZ = countFrameInPlane(false);   // 沿 z 展开
return Math.max(alongX, alongZ);
```

### 开 / 关状态

| 操作 | 效果 |
|---|---|
| 森林法杖右键（关着） | 扣 20 万魔力 → 核心变亮（activated 模型）+ 绿色粒子填充 3×3 |
| 森林法杖右键（开着） | 关门：核心变暗 + 粒子停 + **停止耗魔** |
| 手持物品右键 | 只报状态，**不交易** |

### 持续消耗

```java
// 每 10 tick 扣 250（约每秒 500）
if (!open) return;              // 关着不扣
if (maintainTick % 10 != 0) return;
// 只认「池子 + 上方水晶」的组合
if (drained < need) → 自动关门 + 冒烟 + 音效
```

20 万魔力约能维持 **6.7 分钟**。

### 交易

**唯一的交易方式**：往中间 3×3 空区**丢物品**。

```java
// 每 10 tick 扫一遍掉落物
if (portal == null || !portal.isOpen()) continue;   // 门关着不交易
匹配 elven_trade → 消耗 1 个 → 门上方吐出产物 + 绿色粒子
```

**14 条交易全部生效**（含标签类）：

```
manasteel_ingots（标签）→ elementium_ingot（源质钢锭）
mana_diamond_gems → dragonstone
livingwood → dreamwood
mana_glass → elf_glass
mana_pearl → pixie_dust
...
```

## 三、火花系统

**形态**：`item_display` 实体，悬浮在宿主上方 1.35 格。

**能装的宿主**（3 种，手持 `botania:spark` 右键）：

```
魔力池 / 符文祭坛 / 泰拉凝聚板
```

**接力规则**：

| 项 | 值 |
|---|---|
| 范围 | **圆形半径 16 格** |
| 方向 | 源（下方有魔力的池子）→ 汇（下方缺魔的祭坛/凝聚板） |
| 粒子 | **只在真的搬运时**连一条 END_ROD 光束 |

**拆火花**：拆掉宿主方块时**火花自动掉落**（没有单独拆火花的操作）。

**持久化**：`setPersistent(true)`，重启不丢。

## 四、符文祭坛流程改写

**按上游改成 4 步**：

```
① 投配方材料（手持材料右键祭坛）
② 魔力自动注入（发射器对着灌 / 火花网络送）
③ 魔力注满后，手持活石右键祭坛
④ 森林法杖右键点火 → 出符文
```

**关键改动**：

- **不再自动成型**（魔力满了要等活石）
- **点火不再从池子当场扣魔力**（必须用祭坛自己攒的）
- 活石是消耗品，状态可存档

**各阶段提示**：

| 情况 | 提示 |
|---|---|
| 材料不齐就放活石 | 「材料还没凑齐，先投配方材料」 |
| 魔力没满就放活石 | 「魔力还没注满：3000/5200」 |
| 魔力满但没活石就点火 | 「还没放活石」 |
| 全部就绪 | 「符文完成！」 |

## 五、模型与碰撞修复

### 三个水晶（魔法/自然/盖亚）

**之前用 `sugar_cane`（甘蔗）载体** —— 甘蔗是非满块、**无碰撞**。

**改成树叶载体**，现在有满格碰撞：

| 水晶 | 载体 |
|---|---|
| 魔法水晶 | `oak_leaves[distance=2]` |
| 自然水晶 | `birch_leaves[distance=4]` |
| 盖亚水晶 | `spruce_leaves[distance=5]` |

### 树叶载体防透明

**问题**：树叶的 `distance` 状态控制**渲染透明度**：

| distance | 效果 |
|---|---|
| 1 | **几乎全透明**（最外层树叶） |
| 2~6 | 渐进 |
| 7 | 完全不透明（玩家放置的默认值） |

**之前用 `distance=1~6` + `persistent=false`** → 自然生成的树最外圈跟着变透明。

**修复**：全部改成 `persistent=true` + `distance=2~6`（玩家放不出来、自然也不会生成）。

### 精灵门核心模型

**之前**用方块模型配树叶载体 → **不生效**。

**改成 `entity_renderer`**：

```yaml
closed:
  entity_renderer:
    item: botania:render/alfheim_portal
open:
  entity_renderer:
    item: botania:render/alfheim_portal_activated
```

### 补的渲染物品

```
render/apothecary_default_water    （倒水后的花药台）
render/mana_pool_full              （满魔力池）
render/alfheim_portal              （精灵门关闭）
render/alfheim_portal_activated    （精灵门开启）
render/terra_plate                 （泰拉凝聚板）
```

### 方块名（Jade 显示）

给花药台、凝聚板加了 `settings.name`：

```yaml
name: '<lang:botania.block.apothecary_default>'
```

之前 Jade 显示「沼泽花药台」，是因为方块没配 `name`，用了错误的默认键。
